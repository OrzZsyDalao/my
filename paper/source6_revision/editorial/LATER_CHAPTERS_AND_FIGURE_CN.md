## 2. Framework 图如何学习 Calypso

参考的是 Calypso Figure 4（总览）、Figure 5（数据与模块接口）、Figure 6（处理与输出），不是复制其地图、组件名称或能力。

| 原图的问题 | 参考图值得学习的方式 | 新图如何落实 |
|---|---|---|
| 旧图的海岸示意占用较大空间，但不清楚不同数据在哪里使用 | 输入与模块分层，连接明确 | 顶层三个输入组，下层四个功能模块 |
| 旧图输出写 Top-k audit，不能对应当前两个比较层次 | 输出与论文任务直接对应 | Within each unit：concentration + breadth；Across units：Layer Agreement / Spearman |
| 配对原则隐藏在最终分布图形里 | 在关键接口标注中间对象 | 可行性筛选后同一批 candidate-bearing segments 分到蓝色网络支路与橙色走廊支路 |
| 权重条容易被当成实测结果或忽略其构造 | 用算法对象说明流程，不用装饰数据 | 明确 Count each segment once 与 Allocate unit mass，标出 same segments / equal total mass；不画虚构数值条 |
| 旧暴露率分支只从路径侧接入，未显示候选标记来源 | 多输入对象显式接线 | 暴露分支同时连接全部有效轨迹与跨区域候选 flags，写明分子和分母 |
| 图文对应不明确 | 模块附章节索引 | 图中标出 III-B、III-C/III-E、III-D/III-F、III-G；这些是功能引用而非新执行顺序 |

新版图采用可编辑 SVG 与矢量 PDF，保留图 1 标签。蓝/橙颜色区分两层，独立紫色分支区分轨迹级输出；含文字标签，黑白阅读仍可区分。虚线只表示辅助证据或标记，不表示观测到的真实光缆。评分证据只接走廊分配框；主配对支路不把候选数当新增观测数。
